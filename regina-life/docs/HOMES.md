# Multi-room homes (design and contract), v2

Status: implemented (milestone M5 of `docs/VISION.md`, first slice): three homes, per-room paint, cutaway, move flow, Homes app; verified by 926 unit tests and the desktop and mobile smoke run. Not done: rent, free-form walls, a separate house door on the street map. This file is the single source of truth for the work packages;
`src/data/homes.js` (read its header) is the shared data contract. v2 folds in three independent spec reviews (rules/saves, 3D/rendering,
UI/flow); every "MUST" below exists because a reviewer found a concrete way the simpler wording breaks.

## 1. What the player gets

You start in the **Studio** (today's Unit 204, unchanged). From the phone's **Homes** app (and the apartment computer) you can move up:

| Tier | Rooms | Total cost | What changes |
| --- | --- | --- | --- |
| Studio | 1: `living` | free | Exactly today's apartment. |
| One-bedroom | 2: `living`, `bedroom` | $1,500 | The Studio room becomes the living room; a bedroom (bed, wardrobe, en-suite shower) opens to the north through a doorway. |
| Bungalow | 4 + garage: `living`, `bedroom`, `bath`, `den`, `garage` | $5,000 ($3,500 from the One-bedroom) | Separate bathroom, a den (home office / guest room), a garage with the **Storage** shelf and a car, a yard around the house. |

* Price from tier S to tier T is `price[T] - price[S]` (cumulative home value 0 / 150,000 / 500,000 cents). No downgrades, no same-tier moves. **No rent yet** (ECONOMY.md: no bills exist).
* **Nothing is ever deleted.** Every placed piece that still validates in the new layout (same raw x, z, rot) stays; the rest goes to storage. Owned items, owned paints/floors, balance and everything else carry over.
* The `living` room of every tier has the **same floor rectangle as the Studio**, the same front door, spawn and exit.
* Each room has its own wall paint and floor (Design shelf: pick a room chip, then a swatch). "All rooms" sets the house default and clears every per-room override of that kind.
* The Home view and build mode show the whole house with a **cutaway**; walking uses full walls and ceilings. Build mode has a Walls button (Up / Cutaway / Down) and, on multi-room layouts, a room focus strip so pieces are placeable on a phone.
* Out of scope (do not build): free-form walls, second storeys, fixtures as catalogue items, undo/redo, starter kits, the dog, rent, a separate house door on the street map (every tier is entered through the existing home door; only the entry toast changes).

## 2. State and saves

```js
state.home = {
  owned: {}, placed: [{ id, type, x, z, rot }],      // as today
  wall: 'cream', floor: 'oak', walls: [...], floors: [...],   // default style of rooms without an override; owned styles (as today, with today's grandfathering)
  layout: 'studio',                                   // NEW: 'studio' | 'onebed' | 'bungalow' (missing/unknown => 'studio', checked with own())
  rooms: {},                                          // NEW: per-room overrides { [roomId]: { wall?: key, floor?: key } }
}
```
* `SAVE_VERSION` stays 1. The new fields are additive: `freshState().home` gets `layout: 'studio', rooms: {}`; the existing shallow `{...d.home, ...s.home}` merge supplies them to old saves. **`sanitize()` rebuilds `s.home` field by field, so it MUST resolve `layout` first, validate `placed` and `rooms` against that layout, and emit `layout` and `rooms`** (otherwise every load silently resets a paid-for move).
* `sanitize` keeps a `rooms[roomId]` key only if `roomId` is an own room id of the layout and the style key is known AND in the owned list; it drops pieces whose footprint is not fully inside one room's place rect, that overlap a wall run, and enforces `maxPlaced(state)` (per layout: 60 / 85 / 110; the Studio value is the existing `MAX_PLACED` constant, written once). `sanitize(sanitize(x))` deep-equals `sanitize(x)`.
* Room ids are stable across tiers: the Studio's room is `living` (name "Studio"), so per-room paint survives a move.

## 3. Geometry, exactly (see the header of `src/data/homes.js` for the definitions of floor rect, place rect, bbox, bounds, walls, doorways, yard)

* One-bedroom: `living` = the Studio room. `bedroom` is north: floor `{x0:-4.5, z0:-10.7, x1:4.5, z1:-5.7}`; the Studio's north exterior wall (centre z -5.6) becomes a partition with one doorway; the new exterior north wall is at z -10.8. Studio windows on the north wall are NOT copied (a window must lie within 0.3 m of an exterior wall face with `ry` equal to that wall's inward normal: north 0, south PI, west PI/2, east -PI/2; `validateLayout` enforces it).
* Bungalow: `living` = the Studio room, plus `bedroom`, `bath`, `den`, `garage`; footprint at most 20 x 17 m; every room reachable from the entrance; the garage is entered from the living room or den and has a decorative roller-door wall; `yard: { margin: 3 }`. **Portrait readability:** the long side decides it, so the bungalow bbox must be at most 18 m on its long side; the build-mode room focus (6) is the real answer on phones.
* Every fixture's collide rect lies inside its room's place rect expanded by 0.5; no two overlap; none blocks a doorway; every key point is inside a room, and not inside any collide rect.
* **Reuse legacy rects:** a fixture that exists in the Studio and is unchanged in a later tier (same kind, pose, rot) reuses the Studio's `collide`, `colliders` and `keepout` entries verbatim (looked up by fixture id); derived rects are only for new or moved fixtures. Every layout's keep-out includes the Studio `door` entry zone. Property (measured): every placement valid in the Studio and not touching a new or moved fixture's keep-out, its use spot, the new doorway approach, nor squeezing a path to a new key, is kept by `planMove`. A few hundred placements in the Bungalow (a mattress over the dining table's seat spot, a piece closing the corridor to the new island) are stored on purpose: that is soft-lock protection, and the Homes app says honestly how many go to storage.
* Lights: `ceilingLights[]` and `pointLights[]` entries carry `room`. At most 2 point lights per room and 6 per layout; `dist` no larger than about the room diagonal (the Studio keeps its 16/14, a tuned parity case); none cast shadows; lights are never added, removed or `visible`-toggled at runtime (intensity only). A light switch toggles only its own room.
* `lotOf(layout)` returns (cached per id; pure, no THREE): `{ layout, bbox, bounds, yardRect, rooms:[{...room, place}], walls:[{ id, ...runRect, rooms:[roomOnNegSide, roomOnPosSide] (null = outside), ends:[e0,e1], role, side, doorsAt... }], doorways:[{ wallId, i, x, z, w, axis, rooms:[a,b] }], collide, colliders, keepout, keyPoints, interactables, grid:{x0,z0,cols,rows}, baseline:Set }`. Exported helpers: `roomAt(layout,x,z)` (place rect), `roomAtFloor(layout,x,z)` (floor rect; use this for "which room is the player in"), `validateLayout(layout) -> {ok, errors[]}`, `interactablesOf(layout)` (world positions of every use, ids per the uniqueness rule).
* **Key points** (rules): a cell supports a key point only if it is within 1.1 m of the key AND in the key's room (floor rect, or the doorway band). `lotOf` adds two implicit keys per doorway (0.6 m inside each adjoining room, named `door:<wallId>:<i>:a|b`) and one key at the free cell nearest the centre of every room that has none; derived key names are unique (`<fixture.id>` or `<fixture.id>.<use.id>`); each key carries a `label` used in error messages. The Studio keeps its listed legacy names.

## 4. Rules (core/, pure, server-portable). Layering is a HARD RULE (no import cycles)

`data/homes.js` <- `core/lot.js` (pure geometry: lotOf, roomAt, validateLayout, grid and flood-fill primitives parametrised by an obstacle list; imports only `data/` and `core/util.js`) <- `core/home.js` (itemDef, validatePlacement, canPlace, repairHome, setStyle, styleOf, styleQuote, maxPlaced, homeBonuses; imports lot.js) <- `core/move.js` (NEW: planMove, upgradeHome, tierOptions) <- `core/sanitize.js`. **No module-level evaluation in home.js may depend on lot.js** (`BASELINE` becomes `lotOf(STUDIO).baseline`, lazy; `BASELINE_KEYS` stays exported for the Studio and the existing tests).

* **Walkability.** One grid scheme for every layout: lattice anchored at (-4.05, -5.05): `x0 = -4.05 - 0.25 * ceil((-4.05 - bbox.x0) / 0.25)` and likewise z; CELL 0.25; PLAYER_R 0.38 (one exported constant, replacing the copies in home.js and the controller). A cell is walkable only if its centre is inside some room's place rect, or inside a doorway threshold band (the opening extended into both adjoining place rects), and is not within PLAYER_R of any wall run, fixture collide rect, or placed solid. Cells outside that domain are blocked (this mirrors `bounds`). Flood-fill starts from the entrance with today's "nearest free cell within 0.7 m" rule. (Reviewers measured that a naively bbox-anchored grid flips 5.5% of today's Studio decisions and an unclipped one accepts soft-locks; anchored + clipped flips none.) **Differential test:** `tests/legacy-home.js` is a frozen copy of the old home.js; `canPlace` must equal the legacy `canPlace` for every catalogue piece, rot 0..3, on the 0.25 grid, in the empty Studio and with 10 seeded random fills, and `lotOf(STUDIO).baseline` must equal the legacy baseline.
* **validatePlacement(layout, placed, type, x, z, rot, ignoreId = null) -> {ok, error?}** uses RAW x, z (no snapping), the in-room / wall / keep-out / overlap / reachability rules of the given layout against the given `placed` list. `canPlace(s, ...)` = snap + `validatePlacement(layoutOf(s), s.home.placed, ...)`. (sanitize deliberately does not snap; a test locks that.)
* **move.js.** `planMove(state, tierId)` is pure and deterministic: reject unless `own(HOMES, tierId)` and the tier is strictly higher than the current one ('Already living there' / 'No downgrades'), price a safe integer > 0; iterate `placed` in array order and keep a piece iff `validatePlacement(target, keptSoFar, ...)` is ok; migrate nothing else. `upgradeHome(store, tierId)`: compute the plan ONCE; check the balance; `ledger.debit(price, 'Moved to <name>', { category: 'purchase' })`; only after the debit succeeds mutate (`layout`, `placed` = kept, drop `rooms` keys that no longer exist); commit `'home'` once. All-or-nothing: any refusal leaves state and balance untouched. `tierOptions(state)` -> `[{ id, name, blurb, tier, rooms, area, price, current, owned, canAfford, planned: { carried, stored } }]` using the same plan.
* **Styles.** `setStyle(store, kind, key, roomId = null)`: roomId, when not null, must be an own room id of the layout (else 'Unknown room'); the price is `wallPrice(key)` / `floorPrice(key)` charged once per style key for the whole house; roomId null sets `home[kind] = key` AND deletes `rooms[*][kind]`; a room id sets `rooms[id][kind]`; single-room layouts never write `rooms`. `styleOf(state, roomId) -> {wall, floor}`; `styleQuote(state, kind, key) -> {ok, owned, price, cost}` (cost 0 when owned); `setStyle` returns `{ok, paid}`. (**Pre-existing bug to fix here:** `ui/catalogue-model.js` prices every swatch at the flat cheapest `WALL_PRICE`/`FLOOR_PRICE`, so premium swatches show the wrong price and the toast lies; the model must use `styleQuote`.)
* **Fixture kinds.** Work package A writes ALL `FIXTURE_KINDS` entries (size, `ch`, `pad`, `solid`, `uses`) in its FIRST commit, including the new kinds: `toilet`, `vanity`, `dining_set`, `island`, `guest_bed`, `office_desk`, `garage_shelf` (use: `storage`), `car`, plus whatever the layouts need. B2 builds exactly those kinds (a test asserts `Object.keys(FIXTURE_BUILDERS)` equals `Object.keys(FIXTURE_KINDS)`). Colliders have one source per layout (rows in the layout, or derived from kinds); the builder never invents its own.
* `canPlace` for posters, rugs and other non-solids keeps today's meaning (they may sit anywhere inside a room's place rect except on a keep-out zone).

## 5. World builder (world/, THREE)

* **Frame.** Builders only create visuals. `buildHome` makes `g = new THREE.Group(); g.position.set(x, 0, z); g.rotation.y = rot * PI / 2` and calls `FIXTURE_BUILDERS[kind](g, kit, ctx)`; kit helpers take LOCAL coordinates and parent to `g` (ambient blobs and labels included). Colliders, interactables and lights are created by the framework: colliders from the layout rows (`colliders`, else derived), interactables from `uses` with the position `pose + rotXZ(use.dx, use.dz, rot)`. `rotXZ`/`rotRect` come from `data/homes.js`.
* **Interior API** (`buildInterior('apartment', { layout })`; `layout` defaults to the Studio): returns `{ layout (the object), rooms, bounds (= lot.bounds), spawn, exit, colliders, interactables, group, setHome(home), setOverhead(on), setWallMode(mode), setCameraCut?, dispose(), ... }`. `setHome(home)` returns immediately if `home.layout !== this.layout.id`. `dispose()` disposes every geometry, material, texture (including per-room floor textures, the TV canvas texture) and removes the group's lights.
* **Walls.** Each wall run is ONE box whose two broad faces take the adjacent rooms' wall materials via a 6-material array (order +x, -x, +y, -y, +z, -z; top/ends use the trim material; an exterior wall's outside face uses the adjacent room's material, as today). One `MeshStandardMaterial` per room (`wallMat[roomId]`, roughness 0.92); `setHome` recolours materials, nothing is rebuilt. Run extents follow `ends` (corners and T-junctions extend WALL_T/2, door jambs 0) so the Studio's boxes are exactly today's 9.4 x 11.0. A door emits a threshold floor plane, a lintel box from `DOOR_H` to `CEIL_H` (visual only; tagged `lintel`) and clipped trim.
* **Floors.** One cached texture per floor key with `repeat (1,1)`; each room floor is a plane whose UVs are multiplied by (W/3, D/3) (reproduces the Studio's repeat (3, 11/3)); per-room floor materials (roughness 0.45, metalness 0.02); `setHome` swaps `.map` only; everything goes in `disposables`.
* **Windows.** `windowPane` pane position is `(x + 0.04 sin ry, y, z + 0.04 cos ry)` for every `ry` (the old helper only works for ry 0).
* **Colliders and camera.** Wall runs get tag `'wall'`, height `CEIL_H`; doorways are plain gaps. `CollisionGrid.add(x0, z0, x1, z1, h, tag, y0 = 0)` and `rayBlocked(..., { skip, only })` (B1 owns `world/collision.js`). The walk camera calls `rayBlocked(..., { skip: 'wall' })` so partitions never drag the camera to the player's nose, and `interior.setCameraCut(headPos, camPos)` eases (~0.15 s) every partition mesh crossed by the head-to-camera segment to the cut height; fallback if cut: clamp `t >= 0.5` for wall hits and cap `targetDist` to 2.4 on multi-room layouts.
* **Interactables.** Every interactable carries `room` (from `roomAtFloor`). `nearestInteractable` requires line of sight: `colliders.rayBlocked(px, 0.9, pz, it.x, 0.9, it.z, { only: 'wall' }) >= 1` (a doorway passes), so prompts never work through walls. For placed gear (KIND_ACTIVITY) the standing spot is `pose + rotXZ(0, reach, rot)`; if it is inside a wall or collide rect or across a wall from the item, try the other three sides, else drop the prompt.
* **Sitting.** Seat position = `pose + rotXZ(sit.dx, sit.dz, rot)`; world yaw = `wrap(rot * PI / 2 + sit.yaw)`; `sitAt` receives `stand: {x, z}` (the use's standing spot) and `PlayerController.standUp` places the player there (falling back to +0.9 z only when absent), then resolves against the grid. In this game yaw 0 faces world +z (the character's nose is at +z; the spawn's yaw PI faces north into the room), so a seat whose back is on the local +z side uses `sit.yaw = PI`. The original Studio sofa had yaw 0, so a seated player faced the sofa's back instead of the TV; this was fixed deliberately (the parity tests pin PI).
* **Wall modes.** `setWallMode(mode)` is the only visibility API; modes `'walk'` (full walls, ceiling, ceiling fixtures; the only mode while walking), `'up'` (full walls, ceiling hidden = today's overhead view), `'cut'`, `'down'` (see `src/world/homeWalls.js`). `setOverhead(on)` stays as the one call main.js makes on view changes: `on` applies the overhead mode (default `'cut'` on layouts with 2+ rooms, `'up'` on the Studio so Studio screenshots stay identical), `!on` forces `'walk'`. The overhead camera never rotates (north is screen-up), so "near exterior wall" means the south wall only. The Walls button cycles only up -> cut -> down; the chosen mode is a session variable in main.js, not saved, re-applied after every interior swap. Wall pieces carry `userData.wall = { role, side }`.
* **Performance budgets.** Bungalow furnished with 110 pieces: `renderer.info.render.calls` <= 1,200 in cut mode and <= 700 in walk mode (checked by a `.scratch` script via `__regina.info()`). Merge static fixture detail (fence, pickets, trim, skirting) per material (export `kit()` from `furnitureModels.js`, owned by B2) or instance it; one `THREE.Group` per room (`interior.roomGroups[id]`) so walk mode hides rooms that are neither the player's nor one doorway away, and the yard (meshes only, never lights); `setHome` becomes incremental: `Map<placedId, { sig: `${type}|${x}|${z}|${rot}`, obj }>`, rebuild only changed signatures, one baked template per type cloned with shared geometry and materials (dispose templates only in `dispose()`).
* **Yard.** `lotOf` returns `yardRect` (bbox + `yard.margin`). The yard lives in the interior (`interior.yard`, visible only in overhead modes); the Home stage's grass disc is only the backdrop beyond it.

## 6. UI, camera, phone and the move flow (package C)

* **buildFrame.** `bbox` = union of room floor rects. Export a pure `buildFrame(bbox, { aspect, inset, top, fovDeg = 46 })` from `cameraRig.js` returning `{ x, y, z, lookX, lookZ }`: `th = tan(fovDeg/2)`, `f = clamp(1 - inset - top, 0.4, 1)`, `y = max((hd + 0.4)/(th*f), (hw + 0.5)/(th*aspect))`, `pos = (cx, y, cz + 2 + 0.06*y)`, `look = (cx, 0, cz + 0.2)`. `update()` and `snapBuild()` both call it; `rig.setBuildFrame(bbox)` (default: the Studio's, so behaviour and tests are unchanged); vitest asserts the Studio reproduces today's numbers (5.9 / 5.0 half extents, centre 0, look z 0.2) and sane references for the One-bedroom and Bungalow in landscape and portrait. `rig.setBuildFocus(rect | null)` frames one room's floor rect.
* **Room focus.** On layouts with 2+ rooms build mode shows a chip strip `#b-rooms` (House | Living | Bedroom ...; floating top-left, outside the crowded bottom bar, `[data-act="focus"][data-id]`, hidden for the Studio). Selecting a stored piece focuses the room containing the last edited item, else the living room. Home (non-edit) view stays whole-house. Acceptance: at 390x780 the focused room's place rect renders at >= 30 px/m.
* **Grid.** `gridLines(rooms, step, major)` accepts one rect or an array (existing calls and tests pass unchanged); `makeFloorGrid({ rooms })` keeps three layers (minor, major, border) merged across rooms, with `setRooms(rects)`, `setColor(hex)` (all), `setRoomColors({ [roomId]: hex })`, `dispose()`. `BuildMode.setLayout(layout)` feeds `lotOf(layout).rooms.map(r => r.place)` to the grid (constructor, `start()` when the layout id changed, and from moveHome); `refresh()` tints each room by its floor.
* **Walls button.** `#b-walls`: a fixed 44 px square icon button between Rotate and Store (`<button id="b-walls" class="btn small icon" aria-label="Walls: cutaway" hidden>`), shown only for 2+ rooms, cycling up -> cut -> down, announcing "Walls: Cutaway" in the hint line; `BuildMode` takes an `onWallMode` option (it has no interior reference); guard the constructor lookup and extend the test fake.
* **Design shelf.** `catalogue-model.js`/`catalogue.js` are C's. Backward compatible: `tabView(s, tabId, balance, opts = {})` with `opts.room` (null = All rooms), `designCards(s, balance, room = null)`, `applyStyle(store, kind, key, room = null)`; `view.rooms = [{ id: 'all', label: 'All rooms', active }, ...layout rooms]` (new field; NOT a section, not in `cards`; omitted for single-room layouts; `'all'` is reserved and `validateLayout` rejects it as a room id). For a room, `active` = `styleOf`; for All, active only when every room has that style, else the header shows "Mixed". `Catalogue` holds `this.room` (default null, re-validated each `_render`), `_click` handles `act === 'room'`; chips render in a separate sticky `.cat-rooms` element (not rebuilt by `_swap`). Prices come only from `styleQuote`/`setStyle`'s `paid`. Test: for every WALLS and FLOORS key the displayed cost equals the ledger delta.
* **Homes app.** Phone apps receive the main `ctx` (no `ui` key): add `ctx.moveHome = (id) => moveHome(id)` next to `startTrip`/`quickCab`; the app calls `ctx.confirm('Move to the One-bedroom?', '<one plain sentence: price, N pieces come with you, M go to storage>', 'Move in', () => ctx.moveHome(id))`. Registration touches `src/ui/apps.js` (`APPS`, `const homesApp = app('homes', 'Homes', ...)`), `src/ui/icons.js` (`ICON.homes`, `APP_STYLE.homes`; a missing entry makes the phone home screen throw), `src/ui/phone.js` (add `'homes'` to the page-2 list) and `src/style.css` (tier cards). Cards: `data-tier="<id>"`, `Current` / `Owned` badges, **Move in** `[data-move="<id>"]` only for strictly higher tiers, kept in the DOM but `disabled` with a visible reason when `!canAfford`. `update(topic)` re-renders only on `'home'` or `'bank'` (apps otherwise re-render every needs tick). The apartment computer menu gets `{ label: '🏠 Homes', run: () => ctx.ui.openApp('homes') }` (B1 adds it in the fixture action; the Studio parity test whitelists that one extra menu entry).
* **moveHome(tierId) in main.js, ordered:** (0) refuse with a toast, no fade, no debit, if `fading || creator || camMode || build.active || gameMode !== 'play'` or `!planMove(S(), tierId).ok`; (1) `fading = true; phone.close(); panels.close(); catalogue.close(); closeMap(); closeMapOverview();` then `await fadeTo(true, 450)`; everything below is in try/finally whose finally does `await fadeTo(false, 450); fading = false`; (2) build BEFORE paying: `const next = buildInterior('apartment', { layout: HOMES[tierId] })`; (3) `const r = upgradeHome(store, tierId)`; if `!r.ok`: `next.dispose()`, toast `r.error`, return; (4) if in the apartment: `attachInterior(next)` (the shared function below), then re-apply Home view insets, the wall mode and `build.setLayout`; else just drop the stale cache entry (the next `enterInterior` builds the new layout); (5) toast the layout title. `attachInterior(interior)` is extracted from `enterInterior` and used by both: scene add/remove, `player.grid/bounds`, `rig.grid/bounds`, `setHome`, `setOverhead(homeView || build.active)`, wall mode, `build.setLayout`, `homeStage.fit(lot.bbox)`, `rig.setBuildFrame(lot.bbox)`. The `main.js` `'home'` subscription is guarded by `interior.layout.id === layoutOf(S()).id` (otherwise `upgradeHome`'s commit runs the old interior's `setHome` with the new layout and throws inside `commit`, which the smoke test counts as a failure).
* **Cache invariant.** Interiors are cached as `apartment:<layoutId>`; `enterInterior`, `moveHome` and `newLife` look up `layoutOf(S()).id` and dispose any other apartment entry (covers New Life after a move, bad saves, and moves made while outdoors).
* **Stage.** `homeStage.fit(bbox)` REBUILDS (not scales) the grass disc and ring: centred on the bbox centre, radius `hypot(hw, hd) + 1.5`, ring outside, at y -0.07 under the yard's lawn at 0.
* **Controller.** C owns `src/player/controller.js` for `standUp`/`sitAt` (see 5) and the single `PLAYER_R` import.

## 8. Rules for every package
* Server-portable economy: no UI file computes prices or validity; UI calls `core/` and shows results. No fake data; original Regina-flavoured names only.
* Do not break old tests (`tests/catalogue*.test.js`, `tests/review.test.js`, `tests/life.test.js`, `tests/home-parity.test.js`). Edit a test only when its assumption genuinely changes, and say why in the commit message.

## Decisions (package C1: UI, camera, phone)

Small calls the spec left open; `src/ui/build.js`, `catalogue.js`, `homes-model.js`, `cameraRig.js` and `controller.js` follow them. Hooks C2 must wire: see the C1 report (BuildMode options `onWallMode`, `onFocus`, `onLayout(bottom, top)`; `build.setLayout`, `build.setWallMode`; `rig.setBuildFrame`, `rig.setBuildFocus`; `ctx.moveHome`).

* **`onFocus(roomId | null, floorRect | null)`** passes the room's floor rect as a copy, so main.js only has to call `rig.setBuildFocus(rect)`; the House chip has `data-id="all"` (`'all'` is already a reserved room id) and calls back with `(null, null)`.
* **`onLayout(bottomFraction, topFraction)`** gets a second argument: the share of the screen the focus strip covers at the top (0 in the Studio or while the strip is hidden). main.js should keep `rig.buildTop` at least that large while building, so the focused room is framed under the chips.
* **Auto-focus**: selecting a stored piece (not a placed one) focuses the room of the last edited item (placed, moved or stored), else `living`, but only until the player taps a chip (their choice is then final for that build session); `start()` and a layout change reset it, `stop()` clears the focus (and calls `onFocus(null, null)`) so the Home view is whole-house again. A one-room home never focuses.
* **Wall mode** lives in main.js; `BuildMode.wallMode` only mirrors it for the button. It starts at `'cut'` (the multi-room default of `setOverhead`) and `build.setWallMode(mode)` syncs it without a callback. The hint line shows "Walls: Cutaway" for about 2 s; a placement error still wins over it.
* **Grid tints**: per-room line colours are vertex colours on the merged minor/major layers (the material colour is white then); `setColor(hex)` goes back to one colour for every room. The Studio keeps using `setColor`, so its grid is byte-identical.
* **Build bar on phones**: with the Walls button the bar has six buttons, so at 430 px and narrower (class `has-walls`, set by `setLayout`) each button stacks its icon over its label; the Studio bar is untouched.
* **Design shelf**: the room chips live in their own `.cat-rooms` row (not rebuilt when swatches change, so a focused chip stays focused); `Catalogue.setRoom(id | null)` is the programmatic entry, `Catalogue.room` is re-validated on every draw (a room that no longer exists after a move means All rooms). The Design tab hides the sell-price banner and draws compact swatches (`.cat-design`) so the chips do not push the swatches off a phone-sized sheet. A section's "from $X" is the cheapest priced swatch (from `styleQuote`), not a constant.
* **Homes app**: `update(topic)` redraws on `'home'`, `'bank'`, and also with no topic or `'deferred'` (the phone calls it that way when it opens and after a press, which would otherwise swallow a store change that arrived mid-tap). Other topics never redraw it. A missing `ctx.moveHome` or `ctx.confirm` toasts "Moving is not available right now." instead of throwing.
* **Camera**: the look point eases together with the position (`rig.buildLook`) so a frame change glides instead of snapping its aim; `snapBuild()` jumps both.
* **Controller**: `standUp(grid = this.grid)` resolves against the grid and the room bounds after placing the player at `stand` (or 0.9 m south when the seat has none).

## Decisions (package C2: integration in main.js)

How `src/main.js` wires the rest together; the code follows section 6 literally except where listed here.

* **Cache and swap.** `interiors['apartment:<layoutId>']` holds the one apartment for the layout the save lives in (`homeKey()`); `interiorFor('apartment')`, `moveHome` and `newLife` call `dropStaleApartments()`, which disposes every other `apartment:*` entry except the interior on screen. `attachInterior(next)` takes the previous interior off the scene (calling its `tvOff`) and does everything section 6 lists; `enterInterior` runs `repairHome` before it, `moveHome` teleports the player to the new spawn after it. When the player is NOT in the apartment, `moveHome` keeps the interior it built before paying in the cache under the new key (instead of disposing it and rebuilding on the next entry): same invariant, one build less.
* **Home view during a move.** `moveHome` closes the phone, panels, Catalogue and maps first. If the Home (dollhouse) view is open it stays open: the new interior gets `setOverhead(true)` (default `cut` on multi-room homes), and `homeInsets()` and `rig.snapBuild()` run behind the fade, so the camera is already on the new frame when the screen fades in. `build.active` refuses the move (there is no phone in build mode anyway).
* **Wall mode.** `wallMode` in main.js is the session's Walls choice (`null` = the interior's own default). `onWallMode` stores it and calls `interior.setWallMode`; `attachInterior` re-applies it on multi-room interiors only (so the Studio's overhead view stays `up`), and `build.setWallMode(interior.overheadMode)` keeps the button honest on every swap and every build start. `newLife` resets it.
* **Top inset.** `rig.buildTop = max(Home view's top bar/chips, focus strip)`: `homeTop` and `stripTop` are tracked separately (`applyTop()`) and the strip part is cleared when build mode stops. The Studio has no strip, so its numbers are exactly what they were.
* **Stage.** `homeStage.fit(rect)` rebuilds the disc and ring (centre of the rect, radius `max(11.5, hypot(half sides) + 1.5)`; the 11.5 floor keeps the Studio and the One-bedroom looking exactly as before). `attachInterior` passes `lot.yardRect ?? lot.bbox`, as B2 proposed: the Bungalow's lawn would otherwise overhang the disc.
* **Walking.** Per frame, in a multi-room home: `interior.setViewer(player.x, player.z)` (the builder takes coordinates, not a room id) and, unless the overhead camera is active, `interior.setCameraCut(player.pos, camera.position)`. The walk camera's occlusion ray skips tag `wall` indoors (`cameraRig.js`; the Studio has no wall rects, so nothing changes there). `nearestInteractable` asks for line of sight (`rayBlocked(..., { only: 'wall' })`) only in multi-room homes and only for interactables outside the player's own room; a doorway passes.
* **Garage shelf.** The `storage` action opens the Catalogue's "In storage" tab: `homeBuilder.js` calls `ui.openStorage` (main.js: `catalogue.open('in-storage')`) and falls back to `ui.furnitureShop` for a host without it (a small fix in B1's file; integration found that the shelf opened the plain shop).
* **HUD and toasts.** The entry toast and the HUD place name come from `layout.title` (the HUD uses the part before the dot); the move toast is `<title> · paid $x`, shown after the fade-in. While the room focus strip is up (build mode, multi-room homes) `#toasts` starts below it (`placeToasts()`, inline `top`, cleared when build mode stops), so a toast never sits on the chips.
* **Design shelf and focus.** The Catalogue's `onOpen` calls `setRoom(build.focus)` while building (else All rooms), so the shelf paints the room you are looking at; the chips stay one tap away.
* **Debug handles** (`window.__regina`): `layout` (the id the save lives in), `rooms`, `lot` (pure data), `interior` (the live interior), `moveHome(id)`, `interiorInfo()` (kind, layout, state layout, wall mode, overhead mode, viewer room, player room, visible room groups, yard visible, cache keys, `renderer.info` draw calls/triangles/geometries/textures, bounds, spawn).
* **Phone quirk found while testing** (not changed): `phone.openApp(id)` returns early without opening the phone when `id` is already the phone's current app and the phone is closed, so scripts call `phone.open()` first (every in-game path does).

## Decisions (review fixes)
* **Sit direction.** In this game yaw 0 faces world +z, so seats whose back is on the local +z side (the Studio sofa, the dining chair) use `sit.yaw = PI`. The original Studio sofa had yaw 0 and seated the player facing the sofa's back; fixed on purpose and pinned in the parity tests.
* **One collider source.** `homeBuilder.deriveHome` takes its physics rectangles from `lotOf(layout).colliders` (a listed array wins, Studio fixtures reuse the Studio's measured rows, new fixtures derive from the kind), so the rules and the walls the player bumps into can no longer disagree (the sofa was 13 cm wider in the bigger homes).
* **Gear prompts.** A placed piece of home gear tries four sides at three distances before giving up, so a piano in the Bungalow den or a yoga mat in the garage always offers its prompt.
* **Camera cut.** Wall-mounted plates and signs on a partition disappear with it while the walk camera lowers that wall (no floating light switches).
* **Garage.** The storage shelf is on the garage's north wall with open floor on both sides of the car: the shelf was at the end of a 1.25 m dead end and 47 to 100 percent of ordinary garage placements were refused as "blocks the way".
* **repairHome in a multi-room home** stores the piece whose removal brings back the most key points first (latest breaks ties); the Studio keeps the original latest-first order (pinned by the legacy differential test).
* **TVs count seats house-wide.** `homeBonuses` is not room-aware: a TV's fun is scaled by the best seat tier anywhere in the home. A deliberate simplification for this slice (HOME_CAPS keeps it bounded); per-room grouping is a possible later refinement.
