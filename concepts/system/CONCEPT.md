# SYSTEM — MONOCHROME OS v1.0

**Idea:** the site is the interface of a classified catalogue terminal from 2003, built to archive clothes from the future. It boots (`MONOCHROME OS v1.0 — loading archive… 23 objects`, about 1s on a first visit and a 0.3s flash on repeats, skippable with any key or tap), then every product is a datasheet record (ID `MC-017`, category code, size key-caps, status LED) instead of a shop tile.
**What makes it distinct:** Martian Mono against Big Shoulders Display with chrome-gradient type (`UNKNOWN`, and the footer `MONOCHROME®`); hairline grids, corner brackets, a left scroll ruler and top/bottom HUD bars; status shown only by LED shape and blink (filled = in stock, half = limited, hollow with strike = sold out); stepped, terminal-style motion. The lower sections speak the same language: manifest modules and stats are live meters (bars fill, ticks light, hollow tick = sold out), the event is a log entry with an ARCHIVED stamp on a timeline that runs from the first logged object to today, and the FAQ is a `> help --faq` terminal list.
**Hero:** the emblem sits inside a rotating radar. A small WebGL scene (Three.js r160, vendored, loaded only after the boot screen) shows a ring that scans from wireframe to chrome; each of the 23 objects is a blip that pings when the sweep passes (hover for name and price, click to inspect). It pauses off-screen, in a hidden tab and while a dialog is open. Without WebGL the CSS emblem and sweep remain and the labels change to say so. On phones the order is headline, keys, then the radar so it peeks above the fold.
**Key interactions:** command palette on `/` or Ctrl/Cmd+K (labelled MENU on phones; type to filter objects, jump to sections, set filter/sort, open bag); INSPECT drawer with numbered frames, key-cap option pickers, spec table, and a big Add to bag key that carries the price (`/cart/{variantId}:1`; a real disabled SOLD OUT button when unavailable); `[ ]` steps through objects; browser Back closes the drawer; photos open in true colour (SIGNAL toggle for grayscale) and non-matching shapes sit on a blurred copy of the photo instead of letterbox bars; compare up to 3 objects (full-screen sheet on phones); delivery-route lookup (29 zones, Nigeria included); live Regina and Lagos clocks; deep links such as `#mc-015`.
**Kept from the draft:** product data, filter and sort, sold-out handling, newsletter POST to the store (same hidden fields), FAQ, Instagram and mailto links, prices via Intl in CAD with a visible CAD note. No Fit Studio.
**Fonts and files:** self-hosted in `assets/fonts` (no external requests). Everything is static: `index.html`, `styles.css`, `main.js`, `hero3d.js`, `data/products.js`, `config.js`.
**Touch and accessibility:** every control is at least 44px on touch devices; focus stays on the chosen size key when the spec table redraws; reduced motion skips the boot and all loops with content complete at rest; the page scrolls even if the script fails.
**Known limits:** the grid shows grayscale photos by design and two wordmark shots (sweatshirt, gift card) are shown whole on a backdrop; the 3D scene is a stylised ring, not a model of a product; the wordmark image in the footer is a 700px asset, so it is kept small as a stamp beside the typeset chrome name; the timeline dates come from the product data snapshot and the event is placed by its year only.
