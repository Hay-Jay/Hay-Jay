# MONOCHROME® — CLASSIFIED, multi-page edition

The NEGATIVE concept re-themed as a fictional top-secret mission dossier ("THE MONOCHROME BUREAU", Division of Wearables,
Operation: Wear the Unknown). It is a real multi-page static site: every page is its own URL and its own kind of document.
No framework, no npm packages, no build step at deploy time. The pages are generated by one small Node script and the
generated files are committed next to `src/`, so a host only has to serve this folder.

**This is fiction.** It does not use the real CIA seal, logo or name, and every page says so in the footer
("A work of fiction. MONOCHROME® is a clothing brand and is not affiliated with any government agency.").

## Pages

## Homepage picture, magazine and search hints

* **Homepage photo.** `HOME_COVER` near the top of `scripts/build.mjs` picks the product and which of its photographs is the
  folder cover (`{ handle: 'acid-washed-monochrome-hoodie', image: 3 }`). Change the handle (any product handle) or the
  image number, rebuild, done.
* **The Vision Issue (print magazine).** `scripts/sync-products.mjs` files anything named magazine/publication/zine under
  the category `print`. The build then adds: a home section (`#vision`, "Incoming transmission"), a pop-up on Home, Assets,
  Evidence, Mission, Routes and Debrief ("Requisition a copy": the cart link of its first available variant), its own
  dossier page, a `Print` filter in the register and an entry in the `/` command bar. If the magazine is ever unpublished
  or sold out, the home section, the pop-up, the ticker line and the command-bar entry drop out by themselves on the next
  sync + build (its dossier page and the `Print` filter stay, marked sold out).
  The pop-up never shows on the product pages, waits about 9 seconds on a laptop (12 on a phone, or 60% scroll depth, or
  mouse leaving the window), shows once per 7 days (`localStorage`, guarded), closes with Esc, the backdrop, Close or
  "Not now", and the cover photo is only pre-fetched on a connection that is not Save-Data or 2G.
* **Typing search boxes.** The register search and the file-index search types and clears phrases that exist in the
  catalogue ("acid wash", "hoodie", "necklace", ...). The list is `HINT_POOL` in `scripts/build.mjs`; only phrases that match
  at least one product are used. It stops while the box has text or focus, when it is off screen, and with reduced motion.

## Phones and tablets

`css/mobile.css` is linked with `media="(max-width: 899px)"` after each page's own stylesheet, so a laptop never applies it and
the laptop layout cannot be affected by it. It covers 16px form text (no iOS zoom), safe-area insets, a Declassify switch
in the file index (the lone header icon is hidden on phones), a tighter home cover so the first button is on the first
screen, a fade on the scrolling filter row, the shipping manifest as a list (no sideways scrolling), swipe hints on the
photographs and landscape-phone rules. On the product page the photo area hands sideways drags to the gallery (`touch-action: pan-y`) and ignores mostly-vertical ones.

## Build

```
node scripts/build.mjs                       # regenerate the pages in place (clean folder URLs)
node scripts/build.mjs --preview --out dir   # copy of the site where every folder link is explicit (.../index.html)
node scripts/build.mjs --base-path /sub/     # only matters for 404.html, see below
```

Node 22, standard library only. The generator reads `config.js`, `data/products.js`, `src/partials/*.html` (header,
menu, footer, layout) and `src/pages/*.html`, and writes `index.html`, `shop/`, `products/`, `lookbook/`, `about/`,
`shipping/`, `faq/`, `contact/`, `404.html`, `sitemap.xml` and `robots.txt`. Edit `src/`, `css/`, `js/`, then rebuild.

* **Settings** live in `config.js`: `storeUrl` (the Shopify storefront: cart permalinks, policies, newsletter POST) and
  `siteUrl` (canonical URLs, Open Graph, sitemap). Re-run the build after changing either.
* **Products** come from `data/products.js`. `node scripts/sync-products.mjs` refreshes it from the storefront (it talks to
  the store, so run it deliberately), then rebuild. The build stops with a message if the store data no longer lists
  Nigeria or Canada, because the copy names both.
* **Links work under any base path.** The generator gives every page a relative root prefix (`../`, `../../`) and writes
  `window.MC = {root, idx}` into the page. All script-created links use `MC.url('shop/')`. The preview build sets
  `idx` to `index.html`, so it also works from `file://` and on hosts without directory-index handling.
* **404.html** is served by the host at any missing URL, so relative links would point at the wrong folder. It pins its own
  base from `--base-path` (default `/`) before it requests anything. Hosted at `https://host/sub/`, build with
  `--base-path /sub/`.

## Deploying

Upload the folder to any static host (Netlify, Cloudflare Pages, GitHub Pages, S3, nginx). `netlify.toml` adds security
headers and long caching for `assets/`. If the Shopify store moves to `shop.monochrome.com.ng`, change `storeUrl`, rebuild,
and copy `deploy/_redirects.example` to `_redirects` (it forwards old cart, checkout, account and policy links; product
pages are served by this site and are deliberately not forwarded).

## Behaviour notes

* Works without JavaScript: the index, every product page (gallery, options, price, "Buy on the store" link), the FAQ
  and the shipping table are plain HTML. Scripts add filtering and sorting, option chips (variant, price, availability and
  the `Add to bag` link `${storeUrl}/cart/${variantId}:1`), the declassify lens (hover, press and hold, or the button, reveals true colour), the index/find overlay (`/` or Ctrl+K on
  every page), the global DECLASSIFY toggle (lifts every redaction bar; remembered in `localStorage`, guarded by try/catch) and instant prefetch.
* **Redaction bars only cover decorative joke lines** (for example "Handler: Agent Chrome, Desk 7"). Product names, prices, sizes
  and availability are never redacted. A bar also lifts on hover, focus or tap.
* Page changes use cross-document View Transitions (a redaction-bar wipe; the classification banner stays put). Browsers without them
  simply navigate. `prefers-reduced-motion` turns off transitions, reveals, tickers and the pinned lookbook.
* Reveal-on-scroll is an entrance, never a gate: anything not yet revealed is released a few seconds after load.
* Prices are CAD. Photographs are served from the Shopify CDN with a `width` parameter.
